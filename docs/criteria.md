# 收录与标注规则

本规则用于第一轮人工试标与模型验证。目标是汇集声库演绎作品，优先减少热门目标作品的漏收。

## 两个独立判断

| 字段 | 含义 |
| --- | --- |
| `uses_voicebank` | 当前视频中的声音演绎实际使用虚拟歌手声库，而非只在文字中提到声库、角色或引擎，也不因原曲属于虚拟歌手而成立。 |
| `is_vocal_work` | 视频本身是声音演绎作品，包括歌曲、相声、语调等；以介绍为主的新闻、周边、教学、评介等不属于此范围。 |

普通自动收录要求两个字段均为 `true`。两项相互独立：真人演唱歌曲满足第二项但不满足第一项；用声库播报的新闻满足第一项但不满足第二项。人工尚不能确认的字段暂存 `null`，不强行标为 `false`；它不是模型已完成判断的第三种 boolean 值。

## 典型案例

| 视频内容 | 正常收录结论 |
| --- | --- |
| 虚拟歌手声库演绎的原创曲或翻唱曲 | 收录 |
| 另一虚拟歌手声库翻唱已有的虚拟歌手歌曲 | 收录 |
| 使用声库演绎的相声、语调作品 | 收录 |
| 真人翻唱虚拟歌手歌曲 | 不收录 |
| 虚拟歌手新闻、周边介绍，包含少量试听片段 | 不收录 |
| 无对应声库的纯 AI 生成音乐 | 不收录 |

原曲、标题中的角色名称、投稿分区或发现来源都不能单独决定收录。是否采用 AI 技术也不能替代对声库使用和作品类型的判断。不使用封闭的引擎名单排除新声库。

## 模型输入

第一版只包含 `title`、`desc`、`tags`。投稿者昵称、播放量、发现来源、请求 metadata、人工标签和标注理由均不进入模型输入。

资料获取失败时不调用模型，任务记录为单独的获取失败或不可用状态。合法的空简介与获取失败必须区分；视频删除不能转换成两个 `false`。

人工标注可观看视频、听取音频并核对声库信息。每条标注记录简短依据和可核实的证据位置（如视频时间点），并单独记录文本证据是否足够（`sufficient`、`insufficient`、`uncertain`），以便区分模型分类错误与输入信息不足。人工标注时不先看模型预测。混合演唱、剪辑合集等未明确的边界先记为 `null` 并注明原因，试标后集中确认并补充规则。

## 判断与执行

模型输出与收录执行分开保存。模型返回概率时，由经过验证的阈值转换为 flag；不预设所有模型共用一个阈值。格式正确不代表语义正确。

持久管理员设置可强制收录或排除；普通收录请求与复查不能推翻它。一次绕过检查的请求不等同于持久设置。强制设置只决定收录和追踪，不会把两个内容字段改写为 `true`，也不会掩盖获取或执行失败的记录。

移出使用独立的追踪开关，保留历史数据。获取或推断失败、普通标题或标签变化不应直接导致移出。仅凭文本也无法可靠判断实际音视频是否换源。
